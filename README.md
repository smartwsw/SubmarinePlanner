# 潜水艇规划器

FF14 部队潜水艇的航点规划与收益估算工具。读取本机 AutoRetainer 配置，按掉落估值自动搜索航线。

- 在线试用：<https://smartwsw.github.io/SubmarinePlanner/>
- 本地运行：`node server.js`，然后打开 <http://127.0.0.1:4173>

## 功能

**潜艇配置**：从 AutoRetainer 读出等级与四件配件，按「等级 + 配件」合并同配潜艇；也可手动新增配置，存在浏览器本地。配件下拉用 AutoRetainer 的简写标注（中文 `1`–`5`/`1改`–`5改`，英文 `S/U/W/C/Y` 与 `S+/U+/W+/C+/Y+`）。属性卡片显示探索、收集、速度、航程、耐久、恩惠的合计与部件/等级来源，并附游戏内效果说明。

**航点规划**：按海域列出航点，含需求等级、解锁前置、调查耗时、经验、青磷水消耗和掉落估值。勾选航点后汇总航程占用、总耗时、经验与净收益，并标出这条航线对应的海图名。航程按 AutoRetainer 的算法核算，超限的点位置灰禁用。刷新页面会回到上次规划所在的海图；还没选点时按潜艇当前航线定位。

**多语言**：界面支持中文 / 日本語 / English 切换（右上角），航点名、海图名、配件名与掉落物名都取游戏数据表对应语言的行，切换后立即生效并记在浏览器本地。中文用的是国服译名（`ffxiv-datamining-cn`），日文/英文直接读 xivapi 的 `ja` / `en`。

语言同时决定服务区：中文查国服价格（默认猫小胖-海猫茶屋），日文/英文查国际服价格（默认 Mana-Asura）。服务器下拉只列当前语言对应的服务区（中文区额外列出繁中服的陸行鳥），切语言时跨区会按该区默认值重置并重查价格；在日文和英文之间切换则保留已选的国际服服务器。手动换服务器仍以下拉为准。

**路线生成**：在当前海域枚举 1~5 个点位的组合与顺序，按「掉落估值 / 小时」打分，优先落在 24/48/72 小时整数倍前 35 分钟内。

**规划模式**：默认「价值优先」，按净收益排序。切到「目标掉落优先」后，用搜索框从**全部**掉落物里挑目标，已选的以带 `×` 的标签列出、可单个移除；此时路线按「目标掉落物的期望件数 / 小时」排序，不再看价格，掉落估值列也换成「目标掉落/趟」。目标物按与估值相同的落池权重和恩惠触发率折算，因此探索/收集档位仍影响搜索出来的路线。目标和模式都记在浏览器本地，刷新后恢复。

目标模式下掉落卡片也换成目标视角：每个已选目标一张卡片，写每趟期望件数、折合金币、来自哪些航点的哪个池、收集档对应的数量区间；本航线不掉落的目标留在卡片里标「本航线不掉落」，而不是消失。单价低于 10,000 gil 的目标照样出卡（价值模式的卡片会把它们过滤掉，见下）。

**收益估算**：每个航点有三档探索池，每次只落一个池，探索值决定的是**能落到哪一档**，不是必中最好那档。所以按三池加权求和：`Σ 落池系数 × 概率 × 数量区间中点 × 单价`。落池系数取自众包航行记录里各探索档的实际落池比例（例如满配艇在沉船类航点约 51% / 33% / 16%），数量档由收集值决定。恩惠达标时按实测的第二件触发率（约 82%）折算，不是简单翻倍。单价来自 Universalis（服务区由界面语言决定），取近期成交价的**中位数**，无成交时用挂牌价中位数——不用成交均价，因为一笔离谱成交就能把它拉偏（Mana 服上曾有人以 2.1 亿 gil 挂出红宝石，把均价拉到 130 万，而其余成交都在 1~4 gil）。

**成本扣减**：按 AutoRetainer 的耐久公式计算每趟的修理材料消耗（四部件 `(335 + 航点等级 − 部件 rank) × 7` 取最大值，30000 点耐久摊到可跑趟数），按魔导修理材料市价折算后从收益中扣除。

**价格缓存**：价格不会自动过期，存在浏览器本地。需要更新时点「重新获取价格」，下方显示上次更新时间。只有从没查过的物品和切换服务器后会重新请求。

**低成交量提醒**：掉落卡片的大区日成交量低于 5 件时边框标红，并标出具体成交量。成交量是 Universalis 的 `regularSaleVelocity`，按整个大区统计、不是单个服务器。这只影响显示，估值仍按市场价计算——卖得慢不等于不值钱。

## 托管说明

`server.js` 是本机运行时才需要的：它负责读 AutoRetainer 配置、代理 Universalis 价格。部署到 GitHub Pages 时这些都不存在，页面会进入静态模式——使用内置的示例潜艇（可在界面上改成自己的配置），价格直接向 Universalis 查询（其接口允许跨域）。静态模式下读不到本机配置，这是浏览器沙箱的限制，无法绕过。

## 已知限制

- 配置里只有当前航线，没有「已解锁航点」列表，因此按等级判断可达性，未按实际探索进度过滤。
- 海域最后一点需要打通上一海域的解锁链，当前未跨海域展开完整链路；部分航点依赖额外条件，AutoRetainer 用哨兵值 `9876` 表示「条件未知」。
- 恩惠第二件的物品分布没有公开数据（众包记录的 Additional 字段被来源方直接丢弃），只用到了「确实拿到第二件」的实测触发率；第二件具体掉了什么无法建模。
- 掉落概率和落池比例来自玩家众包航行记录，样本量有限，且各航点的探索档分布并不相同；游戏单次只落一件，实际收入会围绕估值波动。
- 单价低于 10,000 gil 的物品（原木、矿石、晶簇等）计入掉落但不计收益，避免廉价原料摊薄估值；沉船首饰（22500–22507）只能卖店，按 `Price{Low}` 计价且不受该门槛限制。
- 周期约束受可选航点限制：高级航点单点调查就超过 10 小时，严格 24 小时可能只剩 1~2 个停点。

## 数据来源

航点/海域/配件名称与数值取自游戏数据表（`SubmarineExploration`、`SubmarinePart`、`SubmarineRank`）及其国服中文版；解锁关系取自 AutoRetainer `Unlocks.cs`；掉落池取自 Argus `LootTable.json`（源头为 FFXIVGachaSpreadsheet 众包记录），阈值取自 SubmarineTracker；价格来自 Universalis。

日文/英文名称由 `tools/fetch_i18n.js` 从 xivapi v2 的 `SubmarineExploration` / `SubmarineMap` / `Item` 表抓取后写进两个数据文件（配件没有自己的名称列，其显示名取自对应物品行）；落池比例与第二件触发率由 `tools/bake_band_weights.js` 从众包 `Submarines.json` 的 `Stats` 字段烘焙。两个脚本都需要手动重跑，不在构建流程里。
